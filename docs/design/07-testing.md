# 测试

本文定义 gate 的测试分层：每一层测什么、用什么手段、判据是什么。

前六份文档的写法是「规格 + 不变式表 + 决策记录」，这一份的原则与之对应：
**测试打在规格上，不打在实现细节上。** 03/04/05 的不变式表（O1–O14、R1–R16、
W1–W14）、02 的校验规格、06 的状态机与故障注入要求，就是测试的需求清单——
每一条至少对应一个能在测试名里 grep 到编号的用例。

这一版的设计有一个反复出现的教训（见 06 的开头）：**局部证明的正确性组合起来
不成立**。所以测试的重心不在「每个函数对不对」，而在「组合点」——部分写 × WS
帧头、SetCipher × 已入队消息、Pause × 关闭、大帧 × 读缓冲。这些正是两轮评审
挑出 P0 的地方，也是回归最可能再犯的地方。

## 分层总览

| 层 | 对象 | 手段 | 何时跑 |
| --- | --- | --- | --- |
| 1 协议单元 | codec、WS 帧层 | fuzz + oracle + 性质 + 边界表 | 每次提交 |
| 2 组件 | outbound / 入站解析 / 预算 / barrier | 表驱动 + 可编程 fake | 每次提交 |
| 3 单连接状态机 | 06 的全部迁移边 | 故障注入 + 单步 loop 驱动 | 每次提交 |
| 4 端到端矩阵 | 两种传输 × 配置组合 | 同一语料双跑 + 对齐断言 | 每次提交（缩减集）/ 夜间（全量） |
| 5 并发与线性化 | Send/Close/SetCipher/Post 交错 | `-race` + 随机交错 + 事后模型检查 | 每次提交 |
| 6 性能护栏 | 热路径分配、吞吐、常驻内存 | benchmem 硬断言 + 基线趋势 + soak | 分配每次提交；其余夜间 |

层与层的分工线：**下一层只信上一层已经证明的东西。** 端到端矩阵不再逐字节验证
分帧（第 1 层管），只验证语义对齐；状态机层不重复验证编码正确性（第 2 层管），
只验证迁移与资源配平。

## 第 0 层：可编程的边界

不是测试层，是让上面六层成为可能的基建。三个注入点，全部沿着**已经存在的接缝**：

### 可编程 I/O

04 的 `poller` 接口已经是一道接缝；再加一道连接级的 io 接口（`read` / `writev` /
`close`），生产实现直通 syscall，测试实现可编程：

```go
type connIO interface {
	read(fd int, p []byte) (int, error)
	writev(fd int, vec [][]byte) (int, error)
	close(fd int) error
}
```

fake 的能力要求（对应 06 故障注入要求 ①②）：

- `writev` 能在**任意字节位置**返回部分成功——不是「按 iovec 边界」，是按字节。
  半个 gate 帧头、半个 WS 帧头、payload 中间、恰好 chunk 边界，都要能指定。
- 能编排序列：部分写 → `EAGAIN`、部分写 → 真错误、部分写 → 对端 `Close`。
- `read` 同样能在任意位置截断，能注入 `EAGAIN` / `ECONNRESET` / EOF。
- 记录完整的字节流水，供「与一次性写出逐字节相同」的断言用。

**虚调用的成本不构成反对理由**：这层接口包的是 syscall（微秒级），一次接口分派
（纳秒级）在噪声里。这与 05 给 `inbound.feed` 算的账是同一笔。

### 可编程时钟

loop 的 `now()` 从字段注入。五条 LRU、backoff、`wait` 的 timeout 全部以它为准，
于是「29 秒写 1 字节」「`CloseLinger` 恰好到期时收到可写事件」这类用例不需要
真等待，也永不 flaky。

### 单步 loop 驱动

测试模式下 loop 暴露 `step()`：跑**恰好一轮**迭代（分发 → flush → 超时扫描 → 回收），
事件由 fake poller 喂。整个 harness 单线程，第 3 层的每个用例都是确定性重放。
并发只在第 5 层引入。

## 第 1 层：协议单元

02 的[测试要求](02-wire-protocol.md#测试要求)已经定了主体，这里只补充归属与扩展：

**Fuzz（每次提交跑 corpus 回归，夜间跑长时段）**

| 目标 | 断言 |
| --- | --- |
| `FuzzCodecParse` | 任意字节：不 panic、不越界、错误分类只有「数据不足」与「协议违规」两种 |
| `FuzzRoundTrip` | fuzz 派生配置 + 消息序列，编码 → 独立 oracle 解码 → 逐条一致；**AAD 篡改任何一位帧头必须 `Open` 失败** |
| `FuzzWebSocketFrames` | 任意字节流进 WS 帧层：不 panic；违规帧全部按校验清单的步骤序被拒 |
| `FuzzWSFeedSplit` | 同一合法 WS 字节流按任意切分喂 `feed`：投递序列与一次性喂**逐字节相同**（流式解帧 + `maskOff` 续位的直接证明） |
| `FuzzGateCarrySplit` | 同一合法 gate 字节流按任意切分：投递序列一致；2 字节空帧单发不卡 carry（复核修的那个死锁） |

oracle 是**独立实现**的解析器（允许慢、允许分配），与生产 codec 不共享代码。
只 fuzz 解码侧会漏掉编码侧的 bug——这条是 02 定的，双侧都要。

**性质测试必须自证覆盖**：统计线路上出现的压缩帧 / 合并帧 / 加密帧 / 4 字节头帧 /
大帧（> rbuf）数量，**任何一类为 0 直接失败**。防止「全部退化成明文小独立帧」的
回归让断言集体空转。

**边界表**：02 的六行边界 + 05 的 WS 长度切换点（业务长度 123/124、65531/65532，
关压缩关合包）+ WS 控制帧 125/126 + 扩展长度非规范编码（126 编码 100、127 编码
70000）+ close payload 长度 1 + 非 UTF-8 close reason。

## 第 2 层：组件

在 fake io / fake clock 上，不起真 socket。每个组件对着自己文档的不变式表测：

### outbound（03：O1–O14）

- **O3 / O12（最重要）**：预置 stage 2 若干 chunk（含 WS 帧头 chunk），fake `writev`
  在每个可能的字节位置部分写一次，断言最终流水与一次性写出**逐字节相同**。
  这是对第二轮评审 P0-1 的直接回归锁。
- **O2**：部分写期间持续 `Send`，新字节只出现在尾部。
- **O5 / 预算**：`charge`（含 `wireSlack`）→ 编码退还 → 写出退还的三段配平；
  压缩省出的差额、AEAD 撑大的部分、compound 外层头，各自方向正确。
- **O7**：空消息 compound 计量（`frameSize` 口径），`MaxCluster` 贴协议上限的夹取。
- **O13 / cipher barrier**：`Send(A); SetCipher(k); Send(B)` → A 旧密钥、B 新密钥；
  barrier 落在 compound 分组中间 → 分组被切断；连续两个 barrier；barrier 后队列
  为空时 flush 不产出字节。
- **O14 / dirty 发布**：单元层面用受控调度复现「take 清 armed 与 postDirty 竞争」，
  断言 dirty 节点绝不重复挂链（侵入式链表完整性检查）。
- **SendFunc 三阶段**：`fill` 期间 `Close` → commit 返回 `ErrConnClosed` 且预算归零；
  `fill` 返回 `k<0` / `k>n` / error / panic 四种，逐种对 01 的表。

### 入站解析（04/06）

- 大帧路径：1MB 帧按 1、2、3、64KB-1、64KB、64KB+1 字节的粒度切开喂，
  断言只有一次 frameBuf 分配、没有 O(n²) 拷贝（用池计数器证明）。
- carry 上界：任何切分下 carry 占用 ≤ rbuf 容量。
- `Pause` 落在一批数据中间：已读出未投递部分转 carry，`MaxPending` 超限关闭。

### 超时结构（04/06）

- 五条 LRU 各自的入链/移尾/摘除时机（对 06 的表逐行）；
- 排序键单调性：伪造乱序更新必须被断言捕获（debug 模式下链表带校验）；
- linger 不空转：`Draining` 且不可写时，后续 `step()` **零次** `writev`（fake io 计数）。

## 第 3 层：单连接状态机

[06 的故障注入要求](06-connection-state-machine.md#故障注入要求)在这一层落地。
harness = fake poller + fake io + fake clock + 单步 loop + 一个脚本化对端。

**① 迁移表逐行覆盖。** 06 迁移触发表的每一行至少一个用例，测试名含起点与事件。
特别是难到达的边：

- `Draining` 期间收到可写事件 → 排空 → `Detached`
- `Detached` 时仍有在途 `AsyncDo` → `resume` 后才 `OnClose`（含 `resume` 从外部
  goroutine 发起——控制项带 core 引用，不走已失效的 token）
- `Handshaking` 期间 `Close` / 对端断开 / 超时（三种都不发 WS close 帧）
- `Proxy` 头分十次读到、头后紧跟第一个 gate 帧（剩余字节留 carry）
- `OnOpen` 返回 error（不调 `OnClose`）；`OnUpgrade` 拒绝（HTTP 错误响应在出站链里）
- panic 五处（`OnOpen` / `OnMessage` / `Post` / `AsyncDo` / `fill`）各自的配对行为，
  对 01 的状态迁移表逐行

**② 操作合法性表逐格覆盖。** 06 的操作 × 状态表，每个非 `—` 的格子一个断言
（`✗` 格子断言错误值；`Pause` 的 `✗` 断言返回 no-op resume；`Post` 在
`Draining`/`Detached`/`Closed` 断言闭包**不执行**——不仅不报错）。

**③ 字节所有权配平（06 要求 ④）。** 这是 harness 的 **afterEach**，不是个别用例：
每个用例结束时自动断言——

```
reservedWire == 0
每个池的借出计数 == 归还计数（含全局并发池与每 loop slab）
chunk slab 全部归还；loop 配额回到初值
fake io 报告 fd 已关闭；五条 LRU 全空；slots 全空
```

任何用例忘了配平都会在自己名下失败，而不是污染下一个用例。

**④ WS 关闭状态机（05 W13）。** `CLOSE_SENT` 后数据帧不再入队；`CLOSE_RECEIVED`
后入站数据帧不投递但 close 回帧照发；close 帧恰好排在一个部分写的数据帧后面
（FIFO 结构保证，测试锁住它）；握手期不发 close 帧。

**⑤ 时序用例全走 fake clock。** idle 与 pause 互斥计时（暂停不计入 idle）、
`MaxPause` 到期、stall 的 29 秒 1 字节盲区（**断言不关**——盲区是文档承诺的行为，
测试把它钉住，将来加「最老消息年龄」时这个用例改判据）、EMFILE 退避曲线。

## 第 4 层：端到端矩阵

真 socket、真 loop、进程内 client（client 存在的意义就是测试）。

**矩阵**：

```
传输     ∈ { TCP, WebSocket }
加密     ∈ { 无, Overhead()==0, AEAD(16) }
压缩     ∈ { 关, 开(带字典), 开(无字典) }
合包     ∈ { 关, 开 }
平台     ∈ { Linux/epoll, macOS/kqueue }        ← CI 层面的维度
```

同一份**语料与断言集**在所有组合上跑（每次提交跑抽样组合，夜间全量）。
语料覆盖：空消息、1 字节、贴 `MaxMessage`、> rbuf 的大帧、高频小包连发、
`SendAlone` 与 `SendFrame` 混发、`OnMessage` 里回包（in-loop 快路径）。

**语义对齐断言**（05 的对齐表逐行）：投递的消息序列、每批的边界行为、
`OnMessage` 返回 error 停批、close reason 映射、`Handshake()` 的有无。
两种传输跑同一份用例代码——测的就是「一份语义」这个承诺本身。

**专项**：

- PROXY protocol v1/v2 × {Required, Optional, Off} × {有头, 无头, 畸形头}；
- 握手攻击面：慢速发头（`HandshakeTimeout`）、64+1 条头、`MaxHandshakeBytes`
  内含完整请求的一次大 read（复核补的那条）、`\r\n\r\n` 后紧跟数据帧的抢跑客户端；
- `Shutdown`：优雅排空、ctx 到期放弃、在途 `AsyncDo` 不被等待；
- `MaxConns` 满额风暴：断言 backlog 被排空（accept+close），listener 不空转；
- `EMFILE`：用 `setrlimit` 压低 fd 上限触发真实路径（仅 Linux CI）；
- 第三方 WS 客户端互通：至少一个主流浏览器内核所用实现（如 gorilla）作对端，
  防止「自己和自己对话」掩盖协议误读。

## 第 5 层：并发与线性化

全部在 `-race` 下跑（06 要求 ⑤）。

**随机交错 + 事后模型检查**：N 个 goroutine 并发地对同一连接 `Send` / `Close` /
`Post` / `SendFunc`（`SetCipher` 只从串行域内发），随机种子驱动；结束后收集
每个调用的返回值与 fake io 的字节流水，检查：

- 返回 `nil` 的 `Send`：其消息**要么**完整出现在线路上，**要么**在拆除时被丢弃
  且预算已退还——绝不出现「返回 nil 但内存/预算泄漏」；
- 返回 error 的 `Send`：其字节**绝不**出现在线路上；
- `Close` 返回之后发起的 `Send` 一律 `ErrConnClosed`（01 的第三行硬保证）；
- 线路上的消息序列是各 goroutine 各自 FIFO 的一个合法交错（不拆散、不重排单源）；
- 恰好一次 `OnClose`，且其后无任何回调。

**串行域不重叠**：`OnMessage` / `Post` / `AsyncDo` 函数体内部用一个非原子计数器
自增自减，任何重叠在 `-race` 与计数器双重意义上暴露。`AsyncDo` 的三条消除措施
（拒绝重入 / 延迟启动 / 推迟 `OnClose`）各一个针对性用例。

**跨连接隔离**：一条连接 panic / 卡死 / 超限，同 loop 其余连接的吞吐与回调不受
影响（公平性预算的行为面验证）。

## 第 6 层：性能护栏

两级判据，**硬断言**与**趋势**分开——混在一起要么 flaky 要么形同虚设：

**硬断言（每次提交，`testing.AllocsPerRun`）**：

| 路径 | 判据 |
| --- | --- |
| 入站：读 → 解析 → 投递（小帧，池预热后） | 0 allocs/op |
| `Send` 入队（尺寸命中池分档） | 0 allocs/op |
| flush：分组 → 压缩 → 加密 → chunk | 0 allocs/op |
| `Overhead()==0` 的加解密 | 0 allocs/op，且原地（指针断言） |
| `Frame` 广播到 N 条连接 | 每连接 0 allocs（chunk 来自 slab） |

**趋势（夜间，只报警不挡合入）**：吞吐 / 延迟基线对比（固定机器、固定负载谱：
请求-响应小包、单向推送、广播三种），偏离基线超阈值报警。

**soak（夜间，Linux）**：10 万真实连接 × 数小时，混合负载 + 随机断连重连，
断言 RSS 天花板、fd 数回落、goroutine 数回落、`Stats()` 的池 miss 率与
`LoopLagNanos` 稳定。这是「内存必须可以被算出来」（01）的实证一半——
算出来的预算表就是 soak 的断言值。

## 确定性规则

1. **测试里没有 `time.Sleep` 当同步用**。等待都改为：单步驱动（第 3 层）、
   channel 信号（第 4/5 层）、fake clock 推进（一切超时）。
2. **一切随机都带种子**，失败时打印种子与最小化提示；fuzz 崩溃样本入 corpus 仓库。
3. **每次提交的测试必须能在无网络、无特权的环境跑通**；`setrlimit`、10 万连接
   这类需要环境配合的，标记后只在夜间 CI 跑。
4. 第 1–3 层的用例**单线程确定性重放**；并发只属于第 5 层——一个用例要么是
   确定性的，要么是带模型检查的随机交错，不存在「碰运气的并发断言」。

## 命名与覆盖规约

- 直接锁不变式的用例，名字里带编号：`TestO3_PartialWriteNeverReencodes`、
  `TestR15_DrainingNoBusyLoop`、`TestW13_CloseAfterPartialFrame`。
  编号 ↔ 用例**双向可 grep**：从不变式找测试，从测试找规格。
- 02 的校验规格按步骤号引用：`TestCodecStep6_SizeBeforeAlloc`。
- 06 的迁移边按「起点_事件」引用：`TestFSM_Draining_WritableDrain`。
- 覆盖检查是**清单式**的：一个生成脚本扫描三张不变式表与 06 的两张状态表，
  报告没有对应用例的条目——新增不变式而不写测试会在 CI 里亮出来。

## 明确不测的

- **私有函数的白盒断言**（测规格不测实现；组件测试放在包内但只打接缝）。
- **「两份实现有没有漂移」**——一份 gate 帧循环之后这个问题在结构上不存在，
  矩阵测试的职责已升级为查边界（05 的结论）。
- **底层库的正确性**（zstd、`crypto/*`）：只测集成契约（长度、原地、AAD 生效）。
- **真实网络的丢包/乱序**：TCP 之下的事不属于 gate 的规格；对端行为异常
  统一用脚本化对端与 fake io 表达。

## 设计决策记录

### T-D1. 测试打在规格上，编号双向可 grep

不变式表是唯一事实来源（06 确立），测试是它的可执行形态。反过来，没有编号的
测试大概率在测实现细节——重构时它们的失败不携带信息。

### T-D2. syscall 边界做成可编程接口

06 说「这份状态机的正确性不能靠阅读证明」。任意字节位置的部分写/读是两轮评审
全部 P0 的共同触发器，没有可编程 io 就只能靠真网络的运气去碰。虚调用的成本
在 syscall 面前是噪声（与 05 给 `feed` 算的是同一笔账）。

### T-D3. 确定性优先，随机必须带模型

flaky 测试的代价不是重跑，是团队学会忽略红色。第 1–3 层单线程确定性重放；
随机只出现在 fuzz（带 corpus）与第 5 层交错（带事后模型检查 + 种子重放），
两者的失败都可精确复现。

### T-D4. 双侧 fuzz + 独立 oracle

只 fuzz 解码侧，编码侧的 bug（长度溢出、规范编码违规、AAD 拼错头）全漏。
oracle 与生产 codec 不共享一行代码，否则两边一起错、round-trip 照样绿。

### T-D5. 资源配平是 harness 的 afterEach

预算守恒（06 要求 ④）如果做成个别用例，只覆盖写它的人想到的路径。做成每个
状态机用例的自动收尾，**所有**路径的泄漏都会在离它最近的用例名下爆出来。

### T-D6. 性能判据分「硬断言」与「趋势」两级

0 allocs/op 是结构性质，机器无关，可以挡合入；吞吐是环境函数，挡合入必然
flaky。混用两者的后果要么是护栏被关掉，要么是没人再信它。
