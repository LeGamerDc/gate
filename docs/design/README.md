# gate 设计文档

`gate` 是一个面向**海量长连接**（目标 10 万级并发）的 TCP / WebSocket 网关库。
它不定义业务协议，只把「连接管理、拆包、可选加密、发送侧合包与压缩」这几件所有
网关都要重做一遍的事收敛成一个可复用组件。

这一版是重新设计。上一版建立在 `gnet` 之上，能跑、也把性能调到了位，但有相当一部分
复杂度是在**补偿底座抽象的形状**而不是在解决业务问题。这次把两件事分开：先把用户
看到的接口设计对，再决定底下用什么。

---

## 目标

| | |
| --- | --- |
| 规模 | 单进程 10 万级并发连接，消息以小包为主（几十字节到几 KB） |
| 形态 | 库，不是框架。业务 `import` 它，而不是被它托管 |
| 传输 | 裸 TCP 与 WebSocket，对业务层呈现**完全相同**的语义 |
| 平台 | Linux（epoll）与 macOS（kqueue）。Linux 是生产目标，macOS 必须能开发与跑全量测试 |
| 稳态成本 | 入站、出站热路径零堆分配；每连接常驻内存尽可能小 |

## 非目标

明确不做的事，写在这里是为了以后不必反复讨论：

- **上层协议编解码**。业务拿到的是 `[]byte`，protobuf / flatbuffers / 自研格式都与 gate 无关。
- **鉴权、路由、心跳、房间广播语义**。gate 提供广播需要的**机制**（预编码帧），
  不提供房间、订阅这些**策略**。
- **TLS / wss 终结**。前置 nginx / envoy / LB。理由见 [01-server-api.md](01-server-api.md) 的非目标一节。
- **运行时可插拔的 pipeline**（Netty 式）。传输层只有 TCP 和 WS 两种、编解码只有一种，
  为此付出每层一次虚调用不划算。分层在 gate 内部是编译期确定的。

## 约束

1. **一份语义，两种传输。** TCP 和 WebSocket 的入站路径不同，但业务看到的
   `OnMessage` 语义必须逐条对齐（含边界与错误行为）。这一条要由测试矩阵持续验证，
   而不是靠注释承诺。
2. **一份语义，两种 poller。** epoll 与 kqueue 的能力不完全等价（水平/边缘触发、
   跨线程唤醒、定时器、accept 负载均衡都有差异）。公共 API 里**不允许出现**任何
   只有一边成立的概念；差异全部吸收在内部。
3. **绝不静默丢消息。** 要么送出，要么让调用方明确拿到错误。出站积压达到准入上限时
   `Send` 报错（消息从未入队，帧流没有洞）；写失败或帧流已经错位时关闭连接。
   从一条有状态的流中间悄悄抽掉几条消息，只会让对端状态机静默错乱，
   而业务层什么都察觉不到。
4. **业务代码的 panic 不能打死进程。** 每一个回调业务代码的边界都要有恢复屏障，
   爆炸半径收敛到单条连接。

## 分层

```
        业务
          │  Handler[S]：OnOpen / OnMessage / OnClose
          │  Conn[S]   ：Send / SendFrame / Pause / Close
──────────┼───────────────────────────────────────────────
   gate   │  codec      线路协议唯一解析入口（allow 掩码区分角色）
          │  outbound   队列 → 合批 → 拼包 → 压缩 → 加密 → writev
          │  session    连接状态机、生命周期、背压、空闲回收
          │  ws         WebSocket 握手与帧层（只在 WS 模式下存在）
──────────┼───────────────────────────────────────────────
  reactor │  Poller     epoll / kqueue 的窄抽象
          │  Loop       thread-per-core、shared-nothing、连接不迁移
```

三条核心资产与底座无关，无论换不换 reactor 都保留：

- **发送侧合批**：业务只做「入队」，真正的 `writev` 收敛到事件循环上执行，
  一次唤醒摊薄 N 条消息的系统调用开销。
- **先拼包再整体压缩**：100 条相似小消息拼成 30KB 再压，压缩比远高于压 100 次
  （zstd 跨消息复用上下文）。
- **单一 codec + allow 掩码**：一份解析实现，服务端 / 客户端 / compound 子消息
  只是策略字段不同。
